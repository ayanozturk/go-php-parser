# PSL Mago 1.47.4 same-machine comparison, 2026-09-05

## Outcome

This mid-size comparison is **rejected for resource-envelope claims**. Both tools completed every validation, warmup, and measured run with stable accounting, but both process-cold CVs exceeded the 5% gate after the extra-run budget was exhausted. Semantic coverage is also not comparable.

The durable results are parser completeness and harness protocol: PSL now parses every selected PHP file, and `cmd/benchmark` can interleave Mago on the same process-cold contract used for previous-engine baselines.

## Accounting

Every Go validation, warmup, and measured run discovered and parsed 3,361/3,361 PHP files with zero failures, 320,419 LOC, 9,552,408 bytes, and 28,643 diagnostics. The 2026-08-25 PSL validation had rejected this corpus at 65/3,361 parser failures; that completeness gate now passes.

Mago `list-files` reports 3,336 configured source PHP files and 2,280 analyzer files (`list-files --command analyzer`, which applies `[analyzer].excludes` for package tests). Mago completed every run with a stable 2,404 findings: 1,929 errors, 292 warnings, 179 notes, and 4 help findings. Mago does not expose parsed/failed counts for includes, so that narrower internal accounting remains unavailable.

The file sets are not identical: Go type-checks host files under the selected roots, including package tests, while Mago's analyzer command excludes `*/packages/**/tests/*` and uses `vendor/revolt` as an include. Diagnostic totals are therefore not a quality comparison.

## Decision

Accept the parser-completeness and accounting result for pinned PSL. Reject timing and RSS ratios because both CVs missed the contract on this loaded host. Keep the Mago interleave in `cmd/benchmark` and rerun on an isolated host before claiming a PSL resource envelope. Do not treat the raw 2.04x mean or 1.81x RSS observations as a performance outcome.
